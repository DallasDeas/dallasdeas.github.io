Project overview

Objective

Design and troubleshoot a simulated enterprise network with separate client and server VLANs. The exercise brings switching, routing, IP address assignment, address translation, device management, and connectivity verification into one working environment.

Architecture

  • Distribution / core: Multilayer switch providing SVIs and inter-VLAN routing for VLAN 10, 20, 30, and 40.
  • Access: Two access switches connected through LACP EtherChannel bundles configured as 802.1Q trunks.
  • Routing: OSPF adjacency between the core and R1; internal VLAN routes learned by R1 and upstream default-route information present on the core.
  • Services: DHCP client bindings across three VLANs and NAT translations on R1 within a simulated external network.
  • Management: Authenticated SSH access from a client workstation to SW-CORE1.

Verified outcomes

OSPF reaches the FULL adjacency state. LACP port channels are bundled and forwarding their intended VLANs. The router records DHCP bindings and active NAT translations. PC1 reaches the lab server at 192.168.40.40 with four successful ICMP replies; PC2 instead receives destination-unreachable responses.

Verification gaps worth addressing

To prove that PC2's blocked connectivity is caused by your intended ACL, capture show access-lists, the interface configuration showing where the ACL is applied, and test counters or a controlled before/after test. Also consider saving show vlan brief, show ip interface brief, and the SSH-only VTY settings.
